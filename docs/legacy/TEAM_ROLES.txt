FÚTBOL: DIRECTOR GENERAL — EQUIPO DE DESARROLLO / SUBRUTINAS v0.2

1) GAME DIRECTOR
- Propietario de la visión del juego.
- Decide qué fantasía de gestión debe soportar cada sistema.
- Rechaza mecánicas con una decisión óptima demasiado evidente.
- Mantiene el balance entre fútbol, empresa, estadio y carrera del GM.

2) SYSTEMS & ECONOMY DESIGN
- Modela P&L, caja, salarios, CAPEX, demanda, sponsors, merchandising, proveedores y activos.
- Debe validar cada mecánica en club pequeño, medio y grande.
- Diseña costes de oportunidad: cada euro invertido en una vía desaparece de las demás.

3) FOOTBALL SYSTEMS DESIGN
- Tácticas 1–20 por parámetros, perfiles de jugador, encaje, peticiones de entrenador y staff de rendimiento.
- Garantiza que el juego represente dirección deportiva, no microgestión de un simulador de partidos.

4) UX/UI + ART DIRECTION
- Objetivo v0.2: reducir dependencia de texto y tablas.
- Cada área principal necesita un lenguaje visual reconocible: campo táctico, estadio, contratos, sala de fichajes, retail, oficina.
- Produce assets vectoriales, cards ilustradas, diagramas, menús y jerarquía visual.
- Debe hacer que el usuario pueda reconocer un área antes de leer su título.

5) SIMULATION / DATA DESIGN
- Clubes, competiciones, calendarios, jugadores/personal procedurales y seeds reproducibles.
- Separa "talento real" de "información que el GM conoce" cuando entre scouting avanzado.

6) LEAD PROGRAMMER
- Vite + React.
- Estado y motor separados de componentes visuales.
- Acciones de gestión implementadas como funciones puras cuando sea posible.
- Saves versionados; dependencias mínimas.

7) QA GAMEPLAY & BALANCE
- No pregunta únicamente "¿hay bugs?".
- Ejecuta carreras con políticas radicalmente diferentes.
- Busca estrategia dominante, decisiones falsas, economías inevitables y sistemas sin impacto.
- Una versión no pasa QA si cuatro estilos de juego acaban tomando esencialmente las mismas decisiones.

8) QA ACCESSIBILITY & UX
- Teclado, foco, labels, contraste, responsive, scroll, modales cerrables y navegación sin callejones.
- Comprueba que la información visual tenga alternativa textual suficiente.

9) RELEASE QA
- Smoke tests.
- QA de cuatro estrategias.
- Build Vite cuando el entorno permita instalar dependencias.
- Nueva partida, save/load y varias semanas manuales.
- ZIP de código sin documentación Markdown adicional.

CADENCIA
Director -> Systems/Football/Data -> Art/UI -> Programming -> Gameplay QA -> Balance iteration -> Accessibility QA -> Director review -> Release QA.
